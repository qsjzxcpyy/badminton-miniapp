# 微信云开发部署说明

本仓库现在包含两部分：

- `frontend/`：原有 Vue/Vite 网页原型，继续使用浏览器本地数据。
- `miniprogram/` + `cloudfunctions/`：新增的原生微信小程序与云开发版本，比赛数据保存到云数据库。

## 开发者工具配置

1. 使用微信开发者工具导入仓库根目录 `badminton-miniapp`。
2. `miniprogram/config.js` 已配置环境 `YOUR_CLOUD_ENV_ID`。在开发者工具云开发面板选择同一个环境，并确认该环境已授权给当前小程序 AppID `wx0000000000000000`。
3. 在该环境创建数据库集合 `matches` 和 `rosters`（默认参赛名单）。两个集合都设置为“所有用户不可读写”，由云函数执行身份校验后访问；不要开放客户端直接读取，否则可能暴露球员等级和创建者信息。
4. 右键 `cloudfunctions/match`，选择“上传并部署：云端安装依赖”，部署目标必须是上述环境。本地写入环境 ID 不会自动创建环境、数据库或部署云函数。
5. 小程序启动时在 `app.js` 调用一次 `wx.cloud.init({ env: config.envId, traceUser: true })`；云函数保留 `cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })`，使用函数实际部署的环境，不硬编码另一套数据库环境。
6. 点击编译，先创建比赛，再把体验版二维码发给已加入体验成员的朋友。

## 数据安全边界

普通球员通过 `getMatch` / `joinMatch` 只会收到球员姓名、状态、赛程、比分和排名，不会收到 `level`。创建者由微信 `OPENID` 识别，名单、等级和排赛操作只允许创建者执行。比分可以由普通球员提交，不记录操作者身份；云端使用 `revision` 防止两台手机同时写入时覆盖彼此的修改。

比分输入草稿按比赛和当前局保留：自动刷新继续同步赛程与排名，避免覆盖尚未提交的比分；换局时重置输入。双方比分必须明确填写，0 分请输入 0。提交失败时保留输入便于重试。此项修复属于小程序页面，重新编译后生效；手机体验版需更新小程序包。验证见 [比分输入刷新修复记录](docs/verification/2026-10-09-score-input-verification.md)。

## 排赛与等级显示（2026-10-09）

排赛已按 [v3 规则](docs/superpowers/specs/2026-10-09-scheduler-v3.md)统一实现：先确定最终局数配额，允许受控连打换组，检查实际搭档覆盖，等级冲突时按双方实力均衡兜底。名单等级选择同步值、选中位置和文字，并立即保存。追加比赛把全部现有赛程计入历史，保留原有待开始比赛；生成失败不会留下空白比赛。

全等级分布审计：`node scripts/audit-scheduler.cjs 4`；报告保存到 `docs/verification/scheduler-audit.json`。微信排赛/选择器验证：`node scripts/verify-wechat-scheduler.cjs "<微信开发者工具安装目录>"`，页面内模拟云请求并恢复原状态，报告及截图保存在 `docs/verification/`。

2026-10-09 已通过微信开发者工具完整部署 `match` 云函数到 `YOUR_CLOUD_ENV_ID`，并在云端安装依赖。部署任务返回 `success`，复查函数状态为 `Active`。本地模拟器已重新编译，真实 `getMatch` 只读云调用返回 `ok: true`。部署未改动现有比赛或赛程；新生成待开始赛程时采用更新后的算法。 如需在手机体验版看到等级选择界面的修复，还需上传新版小程序。

## 目前限制

本地环境不能模拟微信云数据库和多人微信身份。已验证的是本地排名、比分校验、排赛算法、模拟云函数入口、浏览器交互、微信模拟器页面与构建；真实多人同步需要在开发者工具中配置你的云环境后，用两个微信体验账号实测。

## 排版与预览

电脑端 `frontend/src/styles.css` 保持不变。原生小程序沿用现有浅绿色配色、字体、卡片和按钮外观，仅补齐 WXML 对应的 WXSS 排版；移除微信按钮默认边框/行高带来的尺寸差异，使用可收缩的弹性布局，并预留底部导航及手机安全区。

重新点击“编译”，分别检查加入/创建比赛、比赛、赛程、排名、管理和比分弹窗；建议用 320px、375px 和 414px 宽度预览，并使用真机确认输入框及底部导航。模拟器的测试数据不等于真实云数据库联调。

本地回归检查：`node --test tests/*.test.cjs cloudfunctions/match/tests/*.test.cjs frontend/tests/scheduler.test.mjs`。

微信模拟器回归：先打开项目、重新编译并回到入口页，再运行 `node scripts/verify-wechat-layout.cjs "<微信开发者工具安装目录>"`。首次使用需在开发者工具授权 Codex；脚本检查按钮实际宽度、导航切换和赛程筛选，并截图加入/创建比赛、比赛、赛程、排名、管理及比分弹窗。脚本只注入本地临时页面数据，不提交比分、不创建或修改云端比赛，结束后恢复入口页数据；截图写入系统临时目录。

## 沿用邀请码重新开始比赛（2026-10-09）

创建者输入原来的 6 位邀请码进入比赛，在「比赛管理 → 重新开始比赛」点击「重新开始并安排 15 局」，确认后即可开始新一轮活动。保留比赛名称、邀请码、创建者、球员名单及当前参赛状态；只为正常参赛球员生成 15 局，原有赛程、全部比分和排名清空，无法恢复。普通球员仍用原邀请码进入，通过轮询收到新赛程。

原有「生成 / 重排待开始赛程」继续保留已完成比分和正在进行的小局；「继续加赛 5 局」保留全部现有比赛。「重新开始」用于中途重开或下一次活动，执行前有二次确认，排赛失败保留原数据。云函数 `restartMatch` 仅创建者可调用，并要求最新 `revision`，采用条件更新防止覆盖其他人的新比分。

新赛程显示从第 1 局开始，内部小局编号继续递增，旧页面的比分请求无法写到新比赛。页面丢弃过期快照，切换到新赛程时清空旧比分草稿与历史比分编辑窗口。

本功能需要部署最新的 `cloudfunctions/match`。本地及模拟云入口验证：`node --test tests/*.test.cjs cloudfunctions/match/tests/*.test.cjs frontend/tests/scheduler.test.mjs`。微信模拟器验证：`node scripts/verify-wechat-restart.cjs`，临时模拟数据库、云请求和确认选择，结束后恢复页面；不重置真实云端比赛。


## 页面错误提示（2026-10-09）

原生页面统一将微信 SDK 包装的业务异常转换成可操作的中文提示，不展示堆栈、函数路径、错误码和文档链接；未识别异常使用「操作未完成，请稍后重试」。人数不足、比赛已更新、权限、邀请码、排赛约束、网络与超时分别提示下一步操作。原始异常保留在开发者工具控制台，显示错误时清除旧的成功提示。

此改动位于小程序前端，无需部署云函数。模拟器验证命令：`node scripts/verify-wechat-errors.cjs`，使用临时页面数据与模拟云请求，结束后恢复页面，不修改真实比赛。


## 加赛换组与搭档变化（2026-10-10）

加赛仍沿用完整现有赛程和比分，含历史的续排在满足局数、休息、连打和实力约束后，探索多个质量相近方案并规范化去重。等级冲突时先限制均衡兜底的数量，再从完整方案中随机选择，避免每次追加 5 局选回固定分组。代码位于共享排赛器，微信侧通过更新 match 云函数生效，小程序页面无需改动。

审计：node scripts/audit-scheduler-extension.cjs 2；2356 个连续加赛案例通过。人员变动审计：node scripts/audit-scheduler-history.cjs；576 个案例通过。详细规则和证据见 docs/superpowers/specs/2026-10-10-scheduler-extension.md 及 docs/verification/2026-10-10-scheduler-extension-verification.md。
